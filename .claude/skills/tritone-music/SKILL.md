# Tritone Music: Arrange → Assemble → Integrate

Author a tune as a plain-text transcription, compile it to Tritone assembly,
and link it into the app as a blocking `NAME_play()` routine. Engine ref:
https://battleofthebits.com/lyceum/View/Tritone/

The engine itself comes from a **Beepola** Tritone export with its song data
stripped, `assets/music/tritone_template.asm`. It is both the source of the
shared engine (`--engine`) and the template that `txt2tritone.py` fills with new
song data. Swap in any other Beepola Tritone export (song data optional) to
change the engine, drum kit or volume mode for every tune at once — but keep the
`MUSICDATA:` label and the song-layout marker comment, and make sure neither
string appears earlier in the file: both tools split on the first match.

## The pipeline

```
assets/music/NAME.txt                     (you write this — the arrangement)
   │  tools/txt2tritone.py  (make rule)
   ▼
assets/music/NAME.asm                      (standalone Beepola-style Tritone)
   │  tools/gen_tritone_module.py --name NAME  (make rule)
   ▼
assets/music/NAME_linkable.asm             (PUBLIC _NAME_play + song DATA only)
   │  zcc links it + the ONE shared engine into zxstrategy.tap
   ▼
call  NAME_play()  from C on a static screen
```

Both `.asm` files are generated by the Makefile pattern rules — you normally
only write the `.txt` and add three lines of Makefile/C wiring.

**Shared engine.** The ~300-line Tritone player is factored into ONE module,
`assets/music/tritone_engine.asm` (PUBLIC `TRI_PLAY`, `_tritone_ticks`),
generated once from the template. Per-tune modules contain only their song
data + a wrapper that `CALL`s the `EXTERN TRI_PLAY`, so the engine sits in the
binary once no matter how many tunes you add. All tunes share one
`tritone_ticks` entropy counter (valid right after any `*_play()` returns).

`gen_tritone_module.py --engine` also patches the row-end so the speaker is
only reset (`XOR A; OUT ($FE),A`) on real note-change rows: a pure sustain row
(`$01,$01,$01`, no drum) replays the same channels without the reset+re-setup,
so held notes don't click every row (matters for slow, sustain-heavy tunes).
Contended RAM is NOT the cause of clicks here — with `-zorg=$8000` and 128K
paging locked to bank 0, the engine and data live in uncontended RAM.

## Tritone capabilities & limits

- **3 tone channels** (Lead / Harmony / Bass), each with **8 pulse widths**
  (timbre): `pw 0` = 50% "nessy" square … `pw 7` = thin 8% "coil".
- **1 drum channel**, **24 instruments** in this project's engine
  (`DRUM_SETTINGS` in `tritone_engine.asm`); a drum is one hit per row.
- Pitch range: any note whose add-value ≤ 0x0FFF (roughly C2…B6); Bass in
  octave 3, Harmony/Lead in octaves 4–5 works well.
- Speed is per-pattern (frames per row). Volume balance (equal vs
  quiet-medium-loud L→R) is fixed by the **shared engine**, not the song — to
  change it, regenerate `tritone_engine.asm` from a different-volume template.
- **No** arpeggios, slides, portamentos, or vibrato — the engine has none.
  Fake movement with fast note changes across rows.

## Transcription format

One `BAR` per pattern; `CH1/CH2/CH3` = Lead/Harmony/Bass; optional `CH4 Drum`.
A parser reads only the section after a line containing `ATTACK TABLES` (so
prose/headers above it are ignored). Directives `rows = N` and `speed = N`
(frames/row) make the file self-contained.

```
rows = 8            ; rows per bar (grid resolution; e.g. 8 = one row per 1/8)
speed = 15          ; frames per row (15 @ 50Hz ≈ 0.3s → 1/4=100BPM in cut time)

================ PER-BAR ATTACK TABLES ================
BAR 1
  CH1 Lead :  0:c5      4:G4
  CH2 Harm :  0:Eb4     4:Eb4
  CH3 Bass :  0:C3      4:G3
BAR 2   [speed=12]                      ; optional per-bar speed override
  CH1 Lead :  0:c5  1:d5  2:Eb5@3  3:d5  4:c5  6:Bb4(2)
  CH2 Harm :  0:Eb4 2:G4  4:Eb4 6:G4
  CH3 Bass :  0:C3  4:G3
  CH4 Drum :  0:kick 4:snare
```

Token grammar (per channel line, space-separated):
- **Tone**: `ROW:NOTE[@pw][(dur)]`
  - `NOTE` = `A`–`G` + optional `#`/`b` + octave digit, e.g. `A4`, `Bb4`,
    `Eb5`, `c5` is written `C5` (letters are case-insensitive for pitch;
    always give an explicit octave). Use `OFF` for a key-off (silence).
  - `@pw` = pulse width 0–7 for this note (default from `--pw` / per-channel).
  - `(dur)` = duration in rows; **informational** — a note simply rings until
    the next attack (Tritone sustains), so ties/holds need no markup and rests
    are an explicit `OFF`.
- **Drum**: `ROW:INSTR` where INSTR is `1`–`24` or a name
  (`kick`, `snare`, `hihat`, `tick` …). Drums fire only on listed rows.

### Translating ABC (as in design.md)

- Key signature sets accidentals: **C dorian** → E=Eb, B=Bb, A=A♮.
  **E minor** → F=F#. Apply them when writing note names.
- Octaves: `C,` → octave 3, `C` → octave 4, `c` → octave 5, `c'` → 6.
- Meter → rows: pick `rows` so one row = the shortest note. Cut time `C|`
  with `L:1/8` is 8 eighths/bar → `rows = 8` (one row per eighth). A tune with
  1/16 notes → `rows = 16`.
- `Q:1/4=BPM` → `speed` (frames/row): `frames = round(3000 / (BPM * rows/8))`
  for cut time — or just: seconds-per-row × 50, rounded. Verify by ear/BPM.
- Durations: `c4` = 4 rows; place the attack, leave following rows empty
  (they sustain). `z2` = 2-row rest → `OFF` at that row.

## Steps

1. **Read the source** (e.g. an ABC transcription) and transcribe all three
   channels into `assets/music/NAME.txt` using the format above. Choose `rows`
   and `speed` from the meter/tempo. Keep Bass in octave 3, add drums only if
   the piece calls for them.

2. **Wire the Makefile.** Append only your tune's module to `MUSIC_LINKABLE`
   (the shared `$(MUSIC_ENGINE)` is already first in the list and links once):
   ```make
   MUSIC_ENGINE = assets/music/tritone_engine.asm
   MUSIC_LINKABLE = $(MUSIC_ENGINE) \
                    assets/music/lowlands_linkable.asm \
                    assets/music/NAME_linkable.asm
   ```
   The generic pattern rules (`%.asm: %.txt`, `%_linkable.asm: %.asm`) do the
   rest — no per-tune recipe needed as long as the file is `NAME.txt`. The
   `%_linkable.asm` rule runs `gen_tritone_module.py --name $*` (data only); the
   engine has its own one-off `--engine` rule.

3. **Declare & call from C.** Add it to `include/music.h`:
   ```c
   void NAME_play(void);          /* blocks until any key; loops the tune */
   extern uint16_t tritone_ticks; /* shared: rows played — a PRNG seed    */
   ```
   Call `NAME_play()` from a **static screen** (interrupts stay disabled; it
   returns on any key/joystick press). Never call it from the synced frame
   loop — it owns the speaker and blocks. `src/game.c` shows the pattern in
   `play_music()`: `enter_title()` paints the screen, then puts a banner on the
   hint line, calls `lowlands_play()`, and on return restores the line and
   flushes the key that stopped it. It is a **long operation**, not a state —
   see `docs/DESIGN.md`. Paint before you play: the screen is the only thing
   the player has to look at while the CPU is gone.

4. **Build & verify.**
   ```bash
   make                                  # gen .asm + module, link engine+tune
   z88dk-z80asm -b -o/tmp/x.bin assets/music/NAME.asm   # quick assemble check
   ```
   (`NAME.asm` is the standalone engine+data form — handy for this isolated
   assemble check and for Beepola. The app links the split modules instead.)
   Decode-verify pitches with the round-trip check (see below), then run in
   Fuse (`make run`). NOTE: verify audio in Fuse — ZEsarUX headless has no
   sound and its sparse floating bus emulation slows the app down anyway.

## Verifying an arrangement (decode round-trip)

Confirm the generated bytes decode back to the notes you wrote (add-value is
∝ frequency, A4 = 1258):
```bash
python3 - <<'PY'
import re, math
bs=[]; asm=open("assets/music/NAME.asm").read()
m=re.search(r'^PAT0:(.*?)(?=^PAT1:|\Z)',asm,re.S|re.M)
for l in m.group(1).splitlines():
    l=l.split(';')[0]
    if 'DEFB' in l: bs += [int(h,16) for h in re.findall(r'\$([0-9A-Fa-f]{2})',l)]
N=['C','C#','D','D#','E','F','F#','G','G#','A','A#','B']; i=0
def nm(a): s=round(12*math.log2(a/1258)); mi=69+s; return f"{N[mi%12]}{mi//12-1}"
while i<len(bs) and bs[i]!=0xFF:
    row=[]; b=bs[i]
    if 2<=b<=127: row.append(f"drum{b-1}"); i+=1
    for _ in range(3):
        v=bs[i]; i+=1
        if v==1: row.append('.')
        elif v==0: row.append('OFF')
        else: lo=bs[i]; i+=1; row.append(nm(((v&0xF)<<8)|lo))
    print(row)
PY
```

## Tips for arranging

- **Bass**: root/5th, long notes (whole/half). Octave 3.
- **Harmony**: chord tones, sparser than the lead; sustain for a pad-like feel.
- **Lead**: the melody; give accents a brighter/thinner pulse (`@2`..`@5`).
- Because there's no volume envelope, articulate repeated pitches by
  re-attacking (a fresh `ROW:NOTE` retriggers) and use `OFF` for real rests.
- Loop-friendly tunes: end on the tonic; the player loops the whole song.
- Keep it short — the 48K default song area is ~16 KB (~1 minute).
